# 小电脑建图打点与导航

以下命令都在小电脑上执行，打开两个终端即可。

地图和点位必须来自同一次建图；当前目录已有文件，使用前请核对。
本次优化、已发现的问题和无运动检查命令见 [导航问题解惑与优化说明](导航问题解惑与优化说明.md)。

## 一、建图打点

### 终端 1：启动建图，保持运行

~~~bash
source /opt/ros/humble/setup.bash
source ~/r2_ws/lidar_ws/install/setup.bash
ros2 launch /home/slam/r2_ws/test_demo/map.launch.py
~~~

### 终端 2：等定位就绪后，启动扫图打点

~~~bash
source /opt/ros/humble/setup.bash
source ~/r2_ws/lidar_ws/install/setup.bash
python3 /home/slam/r2_ws/test_demo/maping_mid360.py
~~~

移动车辆扫图，在终端 2 输入：

- 输入 g，按回车：记录当前的位置和朝向为目标点，可重复打点。
- 输入 l，按回车：查看已记录的点。
- 输入 q，按回车：保存地图和点位并退出。

扫图结束后，先在终端 2 输入 q 并等保存完成，再到终端 1 按 Ctrl+C，等 Super-LIO 保存地图并退出。两个程序都退出后再启动导航。

## 二、导航

### 终端 1：启动重定位和规划器，保持运行

~~~bash
source /opt/ros/humble/setup.bash
source ~/r2_ws/lidar_ws/install/setup.bash
ros2 launch /home/slam/r2_ws/test_demo/nav.launch.py
~~~

默认读取 Super-LIO 原生地图 `lidar_ws/src/Super-LIO/src/super_lio/map/map.pcd`。若要单独测试 `test_demo/map3d.pcd`，先转换为兼容的 XYZI PCD（不会覆盖原地图），再用环境变量切换：

~~~bash
python3 /home/slam/r2_ws/test_demo/convert_map3d_for_relocation.py
ros2 launch /home/slam/r2_ws/test_demo/nav.launch.py
~~~

当前默认测试 `map3d_relocation_xyzi.pcd`。切换后必须在 launch 日志确认打印的“重定位地图”路径和 `Load map success` 路径都是 `map3d_relocation_xyzi.pcd`；若 ICP 收敛但实时定位仍在二维图外，说明两张地图坐标不一致。恢复原生地图时使用 `USE_NATIVE_RELOCATION_MAP=1`。

工作区还保留一套范围更大的旧二维地图 `test_demo/maps/map2d.*`。若要复现昨天的地图，使用：

~~~bash
USE_LEGACY_MAP2D=1 ros2 launch /home/slam/r2_ws/test_demo/nav.launch.py
~~~

启动日志中的 `Loading yaml file` 必须显示 `test_demo/maps/map2d.yaml`。只有在排查动态点云是否把路径堵住时，才临时使用 `DISABLE_DYNAMIC_OBSTACLES=1`；它会关闭实时障碍层，不能作为最终避障配置。

### 终端 2：等重定位和规划器就绪后，启动导航

~~~bash
source /opt/ros/humble/setup.bash
source ~/r2_ws/lidar_ws/install/setup.bash
python3 /home/slam/r2_ws/test_demo/nav_mid360.py
~~~

核对程序显示的当前定位和目标点，在提示处输入 y 并回车，开始按打点顺序导航。

需要中止导航时，在终端 2 按 Ctrl+C。确认车辆停止、导航程序退出后，再在终端 1 按 Ctrl+C 退出后台程序。

注意：建图和导航不要同时运行；导航前先退出 hand.py 等其他底盘控制程序。

## 三、导航失败时的只读检测

启动 `nav.launch.py` 后保持终端 1 运行，车保持静止，在终端 2 执行：

~~~bash
cd ~/r2_ws
source /opt/ros/humble/setup.bash
source lidar_ws/install/setup.bash
python3 test_demo/diagnose_mid360.py --seconds 15
~~~

检测会读取雷达、两路里程计、点云、二维地图、全局代价图、TF 和在线参数；不会连接 TCP、发送速度或发布 `/initialpose`。重点核对：

- 必须存在唯一的 `map -> world -> imu -> base_link`，每条边不要有多个发布者。ICP 初始化期间暂时缺 `world -> imu` 是等待状态；ICP 成功后仍缺失才是故障。
- `/map` 范围必须包含实时起点和目标。本次地图的 `y` 上界约为 `10.009`；若实时定位 `y` 大于此值（本次日志是 `12.129`），Navfn 从地图外起点规划会失败，应先检查 ICP 匹配和二维地图是否同次建图。
- `/map` 栅格值 `-1` 表示未知，较高值表示占用；全局代价图的致命值表示该中心点不能规划。中心栅格正常也不能代替 footprint 和整条路径检查。
- `lio.map.save_map=false`、`lio.relocation.update_map=false`、`lio.sensor.blind=0.3`；点云和里程计源时间年龄应接近 0，静止采样时定位不应持续漂移。

也可单独检查 TF：

~~~bash
ros2 run tf2_tools view_frames
ros2 run tf2_ros tf2_echo map base_link
ros2 topic info /tf --verbose
ros2 topic info /tf_static --verbose
~~~
